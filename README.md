# tp91 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。规则编码写得不合规矩、同一条规则编码重复使用、文件路径重复收录、内容为空，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5091>

端口固定为 `5091`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 规则区列出编码、名称、级别、状态、适用文件类型与匹配写法，可以按级别、状态、适用文件类型筛选，也能按编码、名称或匹配写法搜索；支持新建、编辑与删除
2. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面；点编辑会把文件内容拉回来做编辑，支持收录新文件与移出清单
3. 命中清单区顶部可以选定只看某一条规则、某一个文件或者某一个级别，点按规则扫一遍，页面上给出这一轮实际扫到多少条、需要处理多少条、另被忽略压住多少条，并按级别、按规则、按文件分别汇总
4. 对确认要留着的命中，可以点该行的标为忽略，写明忽略理由与复核期限（默认两周后，最早只能选当天），由页面右上角的当前操作者落名；忽略范围精确到规则编码 + 文件路径 + 行号这一处，同一规则、同一文件上的其他命中不受影响
5. 默认命中清单里不再出现已忽略的条目；被忽略的命中若下一轮仍然存在，会在清单下方单独的一块里带着理由、期限、标记人列出来——它还在，只是被压住了，不算修好了
6. 已忽略的命中面板可以看全所有忽略记录：每条记录显示理由、复核期限、由谁在什么时候标记、最近一次扫到它的时间，以及当前状态（仍在被压住、这一轮没再扫到、文件已移出、规则已删除、规则已停用、已撤销）；到期只提醒复核，不会自动恢复成命中；点撤销忽略后，这条命中下一轮回到默认清单
7. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 忽略口径

- 忽略记录的唯一位置是规则编码（比对时不区分大小写）、文件路径（不区分大小写）与行号；只有当前确实扫得到的命中才允许标记，同一位置同时只允许一条生效中的记录
- 每次扫描照常比对所有启用规则：命中先按位置查忽略记录，查到的不进默认清单，单独放进 `suppressed` 返回，并把扫描时刻与当时那一行内容回写到记录的 `lastSeenAt`、`lastLineText`，作为"它还在"的凭据
- 已忽略清单里的状态是查询时按当前规则与文件实时算出来的：同位置仍命中为仍在被压住；不再命中为这一轮没再扫到；行号超出文件、文件移出、规则删除或停用分别给出对应状态
- 复核期限按 UTC 日期比较：当天不算到期，次日零点（UTC）起算已到期；到期后记录继续压住命中，只在扫描汇总与清单里标红提醒
- 撤销不会删除记录，撤销人与撤销时间留在记录里，可在已撤销或全部记录视图里备查；之后在同一位置重新标记会得到一条新记录

## 比对口径

- 只有状态为启用的规则参与比对，停用的规则不会产生命中；如果指定了一条停用的规则，页面上会写明这一轮它没有参与
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按规则编码、文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有两种：启用、停用
- 匹配写法不能为空，最长 60 个字符
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "rules": [...], "files": [...], "ignores": [...] }`。忽略记录带理由、复核期限、标记人/标记时间、撤销人/撤销时间，以及每次扫描回写的最近扫到时间与当时行内容；载入时会丢掉结构残缺的记录，并保证同一位置只有一条生效中的记录。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径              | 说明                                             |
| ------ | ----------------- | ------------------------------------------------ |
| GET    | /api/health       | 服务状态检查                                     |
| GET    | /api/rules        | 规则清单，支持按级别、状态、适用文件类型筛选与关键词搜索 |
| POST   | /api/rules        | 新建规则                                         |
| GET    | /api/rules/:id    | 查看单条规则                                     |
| PATCH  | /api/rules/:id    | 修改规则                                         |
| DELETE | /api/rules/:id    | 删除规则                                         |
| GET    | /api/files        | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files        | 收录文件                                         |
| GET    | /api/files/:id    | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id    | 修改文件                                         |
| DELETE | /api/files/:id    | 把文件移出清单                                   |
| POST   | /api/scan         | 按启用的规则扫一遍，命中按忽略状态分成待处理与被压住两份 |
| GET    | /api/ignores      | 已忽略清单，scope 可取 active/revoked/all        |
| POST   | /api/ignores      | 对某一条命中标忽略（编码+路径+行号、理由、期限、操作者） |
| DELETE | /api/ignores/:id  | 撤销某条忽略，记录保留备查                       |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
