# tp91 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。规则编码写得不合规矩、同一条规则编码重复使用、文件路径重复收录、内容为空，保存时当场就会指出来。确实要留着的命中可以单独标成忽略，写明理由与复核期限，忽略只压住规则编码、文件路径、行号完全一致的那一条，再扫到也不会被当成已经修好。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5091>

端口固定为 `5091`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 规则区列出编码、名称、级别、状态、适用文件类型与匹配写法，可以按级别、状态、适用文件类型筛选，也能按编码、名称或匹配写法搜索；支持新建、编辑与删除
2. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面；点编辑会把路径、内容与备注回填到表单，支持收录新文件与移出清单
3. 命中清单区顶部可以选定只看某一条规则、某一个文件或者某一个级别，点按规则扫一遍，页面上给出这一轮参与比对的规则条数、范围里的文件个数、一共命中多少条、其中多少条待处理、多少条已被忽略压住，并按级别、按规则、按文件分别汇总
4. 确定要留着的命中点忽略，写明理由与复核期限（期限可不填），提交前要在右上角填上当前操作者；默认清单里不再出现已忽略的条目
5. 页面底部“已忽略的命中”单独看全被压住的条目：那一行的内容、忽略理由、复核期限、由谁在什么时候标的，以及它此刻是否仍被扫到；勾“只看已到期仍在的”可以只筛逾期未处理的；取消忽略后下一轮扫描这条命中会回到默认清单
6. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 比对口径

- 只有状态为启用的规则参与比对，停用的规则不会产生命中；如果指定了一条停用的规则，页面上会写明这一轮它没有参与
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按规则编码、文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条

## 忽略口径

- 忽略只认 规则编码 + 文件路径 + 行号 三个定位完全一致的那一条，不会因为忽略一条就放过整条规则或整个文件；同一行被多条规则命中时，每条要分别标记
- 标记忽略必须写明理由，最长 200 个字符，并在页面右上角填上当前操作者；复核期限写成 `年-月-日`，可以不填，填了就不能早于当天
- 只能对这一轮真实扫得到的命中标记忽略，凭编码、路径、行号造一条没扫到的记录会被拒绝；同一条命中不能重复标记
- 已忽略的命中不参与默认清单，但扫描结果里单独放在被压住的分区，总数仍是改动前的条数，能看出它还在、只是被压住，不会当成修好了
- 已忽略清单会回看每条忽略此刻是否仍被扫到：仍在的标明压住中或已过复核期限；文件改动后这一处扫不到了（修好、规则停用、行号上移等），标明这一处已扫不到，而不会再把它算进被压住的条数
- 取消忽略不需要其他条件，下一轮扫描这条命中重新出现在默认清单

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有两种：启用、停用
- 匹配写法不能为空，最长 60 个字符
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "rules": [...], "files": [...], "ignores": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径              | 说明                                             |
| ------ | ----------------- | ------------------------------------------------ |
| GET    | /api/health       | 服务状态检查                                     |
| GET    | /api/rules        | 规则清单，支持按级别、状态、适用文件类型筛选与关键词搜索 |
| POST   | /api/rules        | 新建规则                                         |
| GET    | /api/rules/:id    | 查看单条规则                                     |
| PATCH  | /api/rules/:id    | 修改规则                                         |
| DELETE | /api/rules/:id    | 删除规则                                         |
| GET    | /api/files        | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files        | 收录文件                                         |
| GET    | /api/files/:id    | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id    | 修改文件                                         |
| DELETE | /api/files/:id    | 把文件移出清单                                   |
| POST   | /api/scan         | 按启用的规则扫一遍，返回待处理命中、被忽略压住的命中与汇总 |
| GET    | /api/ignores      | 已忽略的命中清单，含每条此刻是否仍被扫到、是否已过复核期限 |
| POST   | /api/ignores      | 对某一条精确命中（规则编码、文件路径、行号）标记忽略       |
| DELETE | /api/ignores/:id  | 取消一条忽略                                               |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
